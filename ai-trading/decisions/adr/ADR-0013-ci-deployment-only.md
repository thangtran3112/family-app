# ADR-0013: CI is deployment-only

Status: accepted 2026-10-31 (owner). Applied for ai-trading; the expense-tax half is blocked (see Not done).

Decision: the repository is personal and experimental and Actions minutes are the cost, so the pipeline only deploys and guards infrastructure. E2E, integration and unit suites leave GitHub Actions. The tests stay in the repo as local gates: the delivering session runs the ones its change touches before it ships and reports the result (`../AGENTS.md`, "Verification").

Removed: `ai-trading-ci.yml` (the `pull_request` pipeline, 8 jobs: `hub`, `bridge`, `desk-web`, `desk`, `desk-e2e-services`, `scripts`, `desk-caddy-acceptance`, `images`). Kept unchanged: `ai-trading-deploy.yml`, `ai-trading-infra.yml` (Terraform validate on PR, plan/apply on `main`), `expense-tax-deploy.yml`, `expense-tax-cloudflare.yml`, `family-backup-freshness.yml`. The deploy workflows keep their own smoke checks. Two comments in `ai-trading-deploy.yml` that pointed at the deleted file were reworded; nothing else in it changed.

Checked before deleting: `ai-trading-deploy.yml` has one `needs:` (`build`, its own job), no `workflow_run`, no reusable-workflow `uses: ./`; no other workflow references `ai-trading-ci`; no test or script in the repo reads the file (only historical plans mention it). Lost with it: PR-time lint/typecheck/tests for the Hub, Desk, common and contracts; the Go bridge checks (`go vet`, race tests, `buf lint`, `buf breaking`, generate drift); the Desk OpenAPI drift check; Playwright E2E; shellcheck and compose `config` validation; image builds with smoke and acceptance tests. The "Enforce feature source branch" guard was not in this file; it lives in `expense-tax-ci.yml` (`quality` job) and is still active.

Consequences: nothing automated gates an ai-trading pull request any more; local gates are the only ones, so a skipped gate is an unnoticed regression. A failure now shows up at deploy time (the image build and the deploy smoke checks), after the merge. Verified 2026-10-31 with read-only `gh api`: classic branch protection returns 404 on `dev` and `main`. A repository ruleset, "Protect development", does exist on `dev`: it blocks deletion and non-fast-forward, requires a pull request (0 approvals), and requires the status check "Contracts, services, workers, frontends" (the expense-tax `quality` job) with the branch up to date. `main` has no ruleset.

Not done: `expense-tax-ci.yml` is still there, so every pull request to `dev` still pays for its `quality` and `integration` jobs, and the minute saving is mostly not realized yet. Removing it needs three things outside this change: (1) `expense-tax-deploy.yml` fires on `workflow_run` of "Expense Tax CI", so without the CI file expense-tax never deploys again until its trigger moves to `push` on `main`; (2) the ruleset's required check is that CI's job, so with the file gone no pull request to `dev` can merge until the owner drops the check from the ruleset (a settings change); (3) about a dozen guard scripts and tests under `expense-tax-management/` parse `expense-tax-ci.yml` or the deploy trigger (`check-ci-workflow`, `check-phase-1b-workflow`, `check-phase-1d-protected-development`, the mailbox `t2`/`t3`/`t6`/`t6b`/`t7` and dispatch-routing wiring tests, `check-centralized-env`, `production-deployment-boundaries`), and several run in `ci:test`; they must be rewritten or retired in the same change.
