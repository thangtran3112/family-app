# ADR-0013: CI is deployment-only

Status: accepted 2026-10-31 (owner). Applied to ai-trading, then to expense-tax-management in a follow-up commit on the same branch (see "Expense-tax follow-up").

Decision: the repository is personal and experimental and Actions minutes are the cost, so the pipeline only deploys and guards infrastructure. E2E, integration and unit suites leave GitHub Actions. The tests stay in the repo as local gates: the delivering session runs the ones its change touches before it ships and reports the result (`../AGENTS.md`, "Verification").

Removed: `ai-trading-ci.yml` (the `pull_request` pipeline, 8 jobs: `hub`, `bridge`, `desk-web`, `desk`, `desk-e2e-services`, `scripts`, `desk-caddy-acceptance`, `images`). Removed in the follow-up: `expense-tax-ci.yml` (jobs `quality`, `integration`, `no-deploy`; pull requests to `dev`, pushes to `main`). Changed in the follow-up: `expense-tax-deploy.yml` (trigger and event references only). Kept unchanged: `ai-trading-deploy.yml`, `ai-trading-infra.yml` (Terraform validate on PR, plan/apply on `main`), `expense-tax-cloudflare.yml`, `family-backup-freshness.yml`. The deploy workflows keep their own smoke checks. Two comments in `ai-trading-deploy.yml` that pointed at the deleted file were reworded; nothing else in it changed.

Checked before deleting: `ai-trading-deploy.yml` has one `needs:` (`build`, its own job), no `workflow_run`, no reusable-workflow `uses: ./`; no other workflow references `ai-trading-ci`; no test or script in the repo reads the file (only historical plans mention it). Lost with it: PR-time lint/typecheck/tests for the Hub, Desk, common and contracts; the Go bridge checks (`go vet`, race tests, `buf lint`, `buf breaking`, generate drift); the Desk OpenAPI drift check; Playwright E2E; shellcheck and compose `config` validation; image builds with smoke and acceptance tests. The "Enforce feature source branch" guard was not in this file; it lived in `expense-tax-ci.yml` (`quality` job) and went with that file (see the follow-up).

Consequences: nothing automated gates an ai-trading pull request any more; local gates are the only ones, so a skipped gate is an unnoticed regression. A failure now shows up at deploy time (the image build and the deploy smoke checks), after the merge. Verified 2026-10-31 with read-only `gh api`: classic branch protection returns 404 on `dev` and `main`. A repository ruleset, "Protect development", does exist on `dev`: it blocks deletion and non-fast-forward, requires a pull request (0 approvals), and requires the status check "Contracts, services, workers, frontends" (the expense-tax `quality` job) with the branch up to date. `main` has no ruleset.

Expense-tax follow-up (same day, same branch): the first commit left `expense-tax-ci.yml` because three things blocked its removal. Two are done, one is open.

- Deploy trigger (done). `expense-tax-deploy.yml` fired on `workflow_run` of "Expense Tax CI", so deleting the CI file alone would have stopped every expense deploy. It now fires on `push` to `main` with the path filter the CI file used (`expense-tax-management/**`, `common/config/**`, `infrastructure/docker-compose.common.yml`, and its own path in place of the CI file's) plus `workflow_dispatch`, which it did not have before. The `workflow_run` conclusion, branch and repository conditions on `build` and `deploy` became `github.ref == 'refs/heads/main'`, which also blocks a manual dispatch from any other branch. The checkout `ref`, the image tags and `IMAGE_TAG` use `github.sha`. `build` to `deploy`, `environment: production`, the concurrency group and the operator-gated steps are unchanged. A push to `main` now deploys with no test job in front of it.
- Guard scripts (done). Deleted `check-ci-workflow.mjs` and `check-phase-1d-protected-development.mjs` with its test; the latter already failed on `dev` before this change (stale AGENTS.md policy strings and CI paths) and was not part of `ci:test`. In the five mailbox wiring tests and the dispatch-routing test, dropped the test that asserted the CI integration job runs `pnpm verify:phase-0n`; the tests that `verify-phase-0n.mjs` runs each suite stay. Repointed `check-phase-1b-workflow.mjs`, `check-workflow-worker-image.test.mjs` and `check-centralized-env.test.mjs` to the push trigger. Removed the "CI frontend builds use a test Clerk key" test in `production-deployment-boundaries.test.ts`, which only read the CI file. Dropped the `check:phase-1d-protected-development` script and the `check-ci-workflow` step of `verify-phase-1a.mjs`.
- Ruleset (open, owner). "Protect development" on `dev` still requires the status check "Contracts, services, workers, frontends", the `quality` job of the deleted workflow. No workflow produces it now, so no pull request to `dev` can satisfy it, including the one that carries this change, until the owner drops the check from the ruleset. This is a repository setting; nothing here changes it. Also lost: the `feature/*` or `dependabot/*` source-branch guard on pull requests to `dev`; it is a convention only.

Checked after the follow-up: no `workflow_run`, "Expense Tax CI" or `needs:` naming a removed job remains in `.github/workflows/`.
