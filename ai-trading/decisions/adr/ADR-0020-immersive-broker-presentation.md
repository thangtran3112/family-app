# ADR-0020: Practice presents an immersive broker environment, not a guided tutorial

Status: accepted 2026-11-01 (owner's directive, repeated across the practice-route review). Consolidates the presentation-layer decisions of the 2026-11-01 immersive-chart, portfolio, day-list and replay-workspace changes. Builds on [ADR-0016](ADR-0016-practice-broker-ticket.md) (the broker ticket), [ADR-0018](ADR-0018-server-thread-clock.md) (the server clock and Summary transport) and [ADR-0019](ADR-0019-away-orders-fill.md) (away fills).

## The principle

The practice route is meant to read as a **neutral broker terminal**, not as training software. The user trades as if at a real broker: no coaching, no "practice" annotations over the price action, no keyboard-wizard legend, no explanatory walls of text in the working surface. The only persistent tell that this is simulated is the SIMULATED badge (ADRs 0010, 0016), which stays.

## Decision

- **No guided marks on the chart.** The "Practice buy 20", "Practice sell", "Practice exit", "Practice stop" labels and their arrows are removed from the live chart (intraday and swing daily). The chart instead draws the open position as a dashed average-price line (green long / red short) beside the stop line, so the entry stays visible without a tutorial label. Strategy-signal bells and the VWAP/EMA lines are unchanged. The Marks tab and the journal chart keep their labels — those are after-the-fact records, not the working surface.
- **Levels show number-only on the chart; meaning on hover.** Session high/low, prior close and OR high/low once printed their full wording on the price axis and cluttered it, overlapping when prices are near each other. The chart now prints the number only; a tooltip names the level (merged levels read "OR high · Session high") within 6 px of the line. The Levels list below the chart keeps the full names.
- **Click-to-order from the chart.** Clicking a price on the chart marks a dashed line and offers Buy and Sell there, Webull-style, rounded to cents (snapping to a level line within 6 px). The order type is derived from the last print (buy below market = limit, above = stop, at = market; sell mirrored) and placed through the same ticket path, so the cash-only size rule and every refusal come from the same checks as a typed order. It is simulated, off when the day ended / the name is behind the clock / there are no prints yet / on the swing daily view. A cash refusal shows on the Quantity field and the popover stays open.
- **Portfolio is a broker positions list.** The Portfolio reads like Robinhood/IBKR: a header shows the count of open positions, each row carries a green-up / red-down arrow (following P/L sign, not side), the day P/L, the last price and the move since entry, with a $↔% toggle so both figures read as dollars or as percent. % derives from the row model (`entry price × shares`), never recomputed loosely in JSX. Long/short stay as words so a winning short shows a green up arrow.
- **Day list shows only the list.** The Portfolio section and the thread box leave the day-list view (the Portfolio subtab and the thread strip already show them); the left rail keeps only the block-days ladder. This removes the layout jump when tabbing and avoids one surface owning two copies of the same data.
- **Re-scan shows progress and repopulates.** Re-scan is a background job (counting → reading N of M with a progress bar → applying filters → finished, resumable after reload). A finished scan **repopulates** the list — one table, "Scan N · run at … · data through …" — rather than appending a second table; `replay_day_scans` stays as one history row per clock. A starred or opened name the scan no longer matches stays as "No longer matches"; a new name is "New in this scan".
- **Peek opens in a drawer, not a cramped rail.** The stock Peek is a wide drawer (760 px, full height via the shared Dialog) with the price levels in a legend above the chart, so nothing overlaps. Escape/Close/scrim close it and return focus to the Peek button; one at a time.
- **No keyboard shortcuts anywhere in Practice.** The key legend, the `?` overlay, the key chips and every `aria-keyshortcuts` (Space / → / B / S / X / T / N / F / C / digits / ⌘Z) are removed. Clickable Buy / Sell / Close / Stop / Note buttons stay — they are controls, not shortcuts. Escape still leaves full screen. Mark undo (⌘Z) therefore has no UI gesture.
- **Replay left rail is the technical indicators.** The left rail shows RSI 14, MACD (12/26/9 with signal and histogram), VWAP, EMA 9 and EMA 21, each with a short read ("Overbought", "Bullish", "Price above"), computed from `buildChartSeries` over the bars the server has revealed — **not** the live Technicals endpoint, which would look ahead. Too few bars reads "Warming up". This replaces the Session / Plan / Armed-strategies / thread-brief clutter.
- **No Back / End-day bar on a day chart.** A day-trade chart loses the "Back to the day list" link and the End-day bar; the tab strip leads back and the Day list ends the day. A swing day and a standalone session keep their one End control because no other surface can end them yet.

## Consequence

- Practice now reads as a broker terminal with a simulated account: the working surfaces (chart, order, portfolio, day list) are clean of training scaffolding, and every "X is simulated / is a closed historical day" fact is confined to the SIMULATED badge and the honest state wording of ADR-0010.
- The one deliberate exception to "no guidance" is the honest disclosure a *practice* account must make (nothing reaches a broker; dates hidden; what a name did earlier is not scored) — that stays, because removing it would mislead, which ADR-0010 forbids.
