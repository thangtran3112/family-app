# Vibe-Trading US-Stock Committee Gate and Free Consensus: Design

**Date:** 2026-10-12 · **Lane:** open-source Trading Hub · **Status:** written spec amended for owner review; implementation not approved. Sub-project 4 of [01n](01n-vibe-research-quality.md); findings from SP3 [01q](01q-vibe-golden-eval-results.md) drive the safety policy. SP3 landed in dev PR #119.

## 1. Intended outcome and boundary

A family member asking about a US-listed stock receives deep research. An **own** Buy/Sell verdict or numeric price target is released only after a real investment committee approved a defensible disposition for the exact ticker and the server checked independent evidence. If a prerequisite for an own verdict fails, return analysis-only; if only the extra target math fails, a separately approved Buy/Sell verdict may remain but **no own numeric target** is released. Never place, queue, simulate or imply an order. Third-party analyst ratings and targets may be quoted as attributed, dated third-party facts, not the assistant's verdict. No non-US asset recommendation behavior changes in this phase.

Owner decisions in this conversation: launch the committee automatically when an own recommendation/target is requested; progress and tool events may stream but US-stock answer text/reasoning tails wait for the release check; an own target requires SEC-backed valuation arithmetic and assumptions, not Yahoo's target alone; a missing free Finnhub key means analysis-only; use an isolated private Python 3.12 service to call the shared provider registry rather than changing Desk-shared code to run on Vibe's Python 3.11. No paid provider subscription, new vendor account or Jina Reader is authorized.

## 2. Evidence from current code and SP3

- `AgentLoop` emits `text_delta` before `SessionService` stores final messages and checkpoints. A post-storage filter can leak an unreviewed target through SSE or the saved partial answer. Its grounding ledger already has a buffer pathway for actionable market requests; SP4 must extend that path to every US-stock answer that could carry an own verdict or target, not rely solely on prompt wording.
- Both tested models produced an own target in SP3 F17 without a committee. A technically `completed` R07 swarm contained a chair report headed `INCOMPLETE — ANALYSIS ONLY`; terminal state and four completed workers are necessary but not sufficient for permission.
- Shared `ai_trading_common.registry.DataSources` has Finnhub recommendation **counts**, not price targets. Finnhub's `/stock/price-target` is premium-only per its [API documentation](https://finnhub.io/docs/api/company-dps-estimates); Alpha Vantage `EARNINGS_ESTIMATES` is also premium-only per its [documentation](https://www.alphavantage.co/documentation/). `ai-trading/market-data` has no Finnhub key. Vibe's image uses Python 3.11, while `ai-trading/common` declares Python `>=3.12` and raises `SyntaxError` on `fallback.py`'s generic function syntax in 3.11.
- Existing `market-data` service is Python 3.11, bound to the `ahf` network and implements a Financial Datasets-shaped Alpaca/SEC API only. Do not change its API or Desk's provider package to solve Vibe integration by accident.
- The shared Finnhub adapter selects the latest recommendation `period` but `AnalystTargets` drops it and sets `as_of` to fetch time. Fetch time cannot prove the underlying counts are fresh. The owner approved one narrow exception to the Desk-lane boundary: add optional `period: date | None` to the shared vendor-neutral type, populate it in Finnhub (and preserve Eulerpool's period when available), and test the existing registry consumers. Do not change the package's Python floor, provider priority, or any other Desk code.

## 3. Gate, orchestration and output contract

1. Place one release boundary in the shared `AgentLoop`, so the web session route, CLI and MCP callers see the same policy. For US-stock requests, buffer all model-produced answer text and omit `reasoning_delta.tail`; still emit stage, tool and elapsed-time status. Do not checkpoint hidden draft text or stream it through retry/reset branches. Detect US identity using the existing grounding/resolution state; if a market request is ambiguous, buffer and fail closed rather than guess that it is non-US.
2. Classify **own-verdict intent** separately from “what do analysts say?” queries. An own Buy/Sell/target request launches exactly one `investment_committee` preset for the locked US symbol, with session/attempt/run association and the per-chat effort propagated to its workers. A follow-up reuse needs proof bound to the same ticker, as-of window and still-valid evidence; otherwise rerun. Avoid double launches on model retry or reconnection. If the committee cannot complete within this phase's wait budget, do not abandon its run; return analysis-only and leave durable recovery for SP5.
3. The chair emits a typed disposition: `approved` or `incomplete`, exact US ticker, reviewed run ID, completed bull/bear/risk/PM task IDs, as-of timestamp, evidence IDs, review rationale and optional verdict/valuation inputs. The server validates the artifact from its own sandboxed run directory and the provenance of its tool calls. `run.status=completed` with `INCOMPLETE — ANALYSIS ONLY`, a missing/invalid artifact, another ticker, cancelled/failed worker, or a free-text assertion of approval never authorizes an own verdict. Approval is not an order authorization.
4. A released recommendation section is generated **by the server from checked typed fields**, never copied untrusted from a raw model answer. Free-form analysis-only prose undergoes a separate fail-closed policy check for unsolicited own advice/targets, including common paraphrases and multilingual forms. At most two bounded correction attempts can remove unsafe prose without dropping supported analysis; if uncertain, emit a fixed analysis-only notice rather than leaking a draft. A deterministic scanner plus an independent classification verdict is defense in depth, not a mathematical guarantee about unrestricted language; persist the check verdict and suppress hidden text from SSE/history/checkpoint paths.

## 4. Private consensus bridge (same Vibe app group)

- Create a small Python 3.12 read-only HTTP service in the open-source lane, using `ai_trading_common.registry.DataSources.from_env` with the `targets` chain pinned to `finnhub`. Do not import a provider module directly, copy its client into Vibe, or lower the shared package's Python floor. The only shared-library edit is the owner-approved additive `AnalystTargets.period` field and provider-adapter tests above. Build the bridge from the shared source/lock with the repo's Docker Bake/CI patterns; its package only returns normalized US symbol, the **source's** recommendation period (not fetch-time `as_of`), strong-buy/buy/hold/sell/strong-sell counts, provider and retrieval timestamp. It **cannot** return a price-target number because the free feed has none.
- Compose places the bridge on the private `vibe` network, without a host port or Caddy route; non-root, read-only filesystem, no-new-privileges, bounded memory/processes and healthcheck. Vibe's existing API key authenticates the internal request; derive a minimal bridge env file containing only the internal auth value and Finnhub key from Firestore-rendered profiles. Never give the bridge OpenAI/Anthropic/Alpaca keys, never give Vibe the Finnhub key, never print any key. Integrate atomic env staging/rollback and group-aware app start/stop rather than reviving an off Vibe container during deploy.
- Finnhub key is not currently configured. Missing/rejected/expired key, non-US symbol, absent/zero counts, missing or stale **source** period (proposed max 45 calendar days), timeout or error returns a typed unavailable result; the gate then releases analysis-only. `AnalystTargets.as_of` remains retrieval time, never a substitute for source period. Store the free key only through `common/config/family_config.py` when the owner supplies it; no dashboard/manual infrastructure changes. A bridge missing its optional provider key must not fail the other three upstream apps' deploy.
- Cross-check Yahoo's `get_stock_profile` recommendation trend against Finnhub's independent directional count for a comparable period. Analyst universes/counts need not match exactly. A disagreement is shown to the chair and must be explicitly discussed in its typed rationale before approval; no silent source selection or averaging. If Yahoo recommendation evidence is absent/stale, an own verdict/target is also withheld. Yahoo's numeric analyst targets remain visibly attributed third-party data, never proof of the assistant's target.

## 5. Own target and valuation math

A numeric own 12-month target additionally requires a reproducible valuation record: exact filed SEC accession/period, per-share earnings (with split/share basis), a stated growth scenario and multiple assumption, as-of quote, horizon, units, confidence range and the worker evidence IDs. The server recomputes `target = projected EPS × assumed P/E` using `Decimal`, checks issuer identity, filing date/period, share basis and a bounded calculation tolerance, and renders the numeric field itself. Assumed growth/multiple are labeled assumptions, not data-provider facts. Missing filed data, uncertain split adjustment, unsupported estimate, failed arithmetic or unresolved source contradiction means **no own target**; an otherwise approved Buy/Sell may still be rendered if its separate committee and consensus prerequisites passed. No model-invented DCF intrinsic value or paid analyst-price feed is introduced.

## 6. Failure behavior and verification

- Before any unreviewed result becomes visible: unauthorized own recommendation → checked analysis-only answer; live-order attempt → existing trading mandate gate remains unchanged and SP4 never invokes it; provider failure/timeout → analysis-only; process crash/restart → no previously hidden draft rehydrated as a completed reply. Keep per-request run and evidence IDs in the run artifact for audit without logging secrets.
- Offline tests cover intent (own vs attributed consensus), two concurrent turns, retry/reconnect, no duplicate swarm, ticker mismatch, forged run ID, all worker/decision states (including terminal `completed` with incomplete chair), missing/stale/conflicting Finnhub/Yahoo evidence, no-key bridge, failed SEC provenance/share splits/arithmetic, 3.11↔3.12 HTTP boundary, and every output path (SSE `text_delta`/`reasoning_delta.tail`, checkpoint, history, CLI/MCP). The same F17 and R07 golden cases must change from a policy violation / safe incomplete response to a correctly gated result, without weakening numeric grounding tests.
- Fork changes remain on `family-app` branch, with `DIVERGENCE.md` updated and fork pushed before superproject pin moves. Run fork backend/frontend tests, `pnpm test`, image Bake/Caddy smoke, bridge/deploy offline tests and real sponsored-model plus signed-in browser checks. CI uses dummy keys; live Finnhub corroboration requires the owner's free key. After owner-approved spec and plan, deliver a scoped `dev` PR, scoped `main` release and deployment under standing authorization; verify live that missing-key analysis-only works and that no partial target leaks. SP5 separately makes multi-minute runs deploy-safe/recoverable.

## 7. Explicit limitations and open review points

- The output policy checker is defense in depth around structured issuance; it cannot *prove* the absence of every semantic paraphrase in arbitrary natural language. This is why raw unreviewed recommendation prose is never streamed or emitted as the server's own verdict field.
- Finnhub's free trend counts and Yahoo's cohort may disagree for legitimate coverage reasons; a human should review the proposed 45-day freshness and chair-rebuttal rule in this spec, not silently turn one source into an oracle.
- The internal bridge increases VPS RAM and image size. Measure both during build/deploy; use the shared VPS free-disk guard and touch only ai-trading-owned containers. If memory cannot support the extra service, stop and revisit the approved boundary instead of weakening the gate or changing Desk-shared code beyond the narrowly approved additive period field.
